# 2026-07-31

## Bitcoin Core regtest acceptance

The isolated Bitcoin Core v31.1 gate first returned the sanitized
`bad_coinbase_height` proposal category. Core's consensus comparison uses
`CScript() << height`; on regtest's immediately active BIP34 deployment,
heights 1 through 16 therefore require `OP_1` through `OP_16`. Hashsphere had
used a direct byte-vector push for every height. A narrow regression test
proved the boundary before the encoder was corrected.

The next fresh wallet-free, loopback-only regtest gate accepted the complete
production-built block, submitted it exactly once, and advanced the isolated
chain from height 0 to 1. The child process stopped and its temporary data was
removed. No mainnet node, wallet, CKPool process, or Stratum command was used.
