# 2026-07-29

## Graceful Time-Bounded Mining

Continuous mining now accepts `--max-runtime-seconds` as an optional positive
finite decimal duration up to 31,536,000 seconds. The monotonic clock begins
when the command enters its active lifecycle after configuration and backend
selection. Deadline expiry produces the successful `runtime_limit_reached`
outcome, one terminal `command_completed` event, and the same aggregate summary
and cleanup path as other controlled outcomes.

The existing SIGINT and SIGTERM scope was verified and extended with
deterministic coverage. The first signal requests cooperative stop, repeated
signals are idempotent, prior handlers are restored, and no new range or
reconnect attempt begins after the stop is observed. A non-cancellable backend
call may finish its current range before the selected backend, Stratum session,
and event sink close.

The preceding CUDA measurements recorded approximately 323.9 MH/s offline,
312.7 MH/s in a controlled CKPool test, and 311.9 MH/s across a 20-minute run
covering approximately 382.9 billion hashes. The endurance run had no
connection losses, reconnects, submissions, or command failures. Its external
timeout arrangement did not deliver a graceful terminal record and eventually
forced exit status 137, leaving JSONL incomplete. That was a process-control
failure rather than evidence of CUDA correctness or stability failure. The
internal runtime limit removes the normal bounded-run dependency on wrapper
signal forwarding.

No live Stratum command was run while implementing this milestone. The record
contains no credentials, payout address, job or run identity, work bytes,
targets, nonce or candidate material, protocol payload, or hardware identifier.

## Stale Session and Work Liveness

The clean internal-runtime CUDA endurance gate completed 360,982,285,568 hashes
across 756 ranges in 20 minutes at approximately 300.76 MH/s. It ended with
`runtime_limit_reached` and a complete terminal JSONL event after 41 received
jobs, 40 replacements, 114 work variants, and 73 extra-nonce advances. No
connection loss, reconnect, or command failure occurred.

Hashsphere now offers disabled-by-default monotonic server-silence and job-age
limits. Work completion is tracked separately and cannot disguise server
silence. A configured stale transition suppresses old-session candidates and
uses the existing recovery owner for fresh subscription, authorization,
difficulty, job, and extra-nonce state. Portable socket keepalive is enabled
with OS defaults. Automatic suspend inference remains deferred because clock
behavior differs across supported platforms and ordinary scheduling gaps are
not reliable proof of suspend.

No live Stratum command was executed while implementing the liveness policy.
